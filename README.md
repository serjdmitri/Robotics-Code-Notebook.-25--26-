## Driver Control

Tank drive with a three-motor intake stack and four pneumatic toggles.

| Input | Action |
| --- | --- |
| Left / right stick | Tank drive |
| R2 | Intake, hood down |
| L2 | Intake, hood up (score into the middle goal) |
| R1 | Reverse the stack (outtake) |
| L1 | Slow feed for controlled scoring |
| B | Toggle wings (descore) |
| Right | Toggle park |
| Down | Toggle match loader |
| A | Run the scoring macro |
| X | Toggle the PID tuner (not at competition) |
| Left + Up | Run the selected autonomous from opcontrol (not at competition) |

The tuner and the autonomous trigger turn themselves off when a field controller is connected, so they can't fire during a match.

### Scoring macro

`SkillsMacro()` in `globals.cpp` is a timed sequence on the A button. It alternates short outtake bursts with longer intake stages on all three motors, and the intake power steps down gradually so blocks seat into the goal instead of falling out at the end. The brief reversals also clear jams. The notebook explains the reasoning on page 309.

There is also a disabled `antiJamTask()` prototype (commented out in `globals.cpp`) that watches motor power against velocity and reverses the stack for 250 ms when it detects a stall. Jams cost us matches at Sabre Tech, so this is the direction for future work.

## Autonomous

### Structure

Every routine is built from a small set of wrappers in `autons.cpp`, so the routines read like a script instead of repeating PID calls:

| Function | What it does |
| --- | --- |
| `drive(in, speed)` / `turn(deg, speed)` | PID move that waits until it settles |
| `mcdrive` / `mcturn` | "Motion chain" versions that hand off to the next move early (`pid_wait_quick_chain`) |
| `Lswing` / `Rswing` / `Lmcswing` / `Rmcswing` | Swing turns, with and without chaining |
| `topIntake()` / `outake()` / `middle()` / `inStop()` | One call for all three intake motors instead of three lines every time |

Mechanisms fire mid-motion with `pid_wait_until(...)` so the match loader or hood triggers at a set distance into a drive instead of after it.

### PID tuning

Constants live in `default_constants()` in `autons.cpp` and were tuned with the on-brain PID tuner:

| Controller | kP | kI | kD |
| --- | --- | --- | --- |
| Drive | 13.0 | 0 | 110.0 |
| Heading | 11.0 | 0 | 20.0 |
| Turn | 3.7 | 0.05 | 25.0 (start I at 15) |
| Swing | 6.0 | 0 | 65.0 |

Chain constants (4 deg for turns, 3 in for drives) control how early a chained motion hands off to the next one.

### Routines

The brain screen selector (in `main.cpp`) lists every routine. Match-play routines are chosen by side and by what the alliance partner can do.

| Routine | Purpose |
| --- | --- |
| `sigSoloAWP`, `TSAWP` | Solo autonomous win point. Clears, collects and scores everything needed without relying on the partner. Hardest to keep consistent. |
| `R63`, `L63` | "6 and 3": 6 blocks in the top goal and 3 in the middle goal, worth 60% of the win point. Used when the partner covers the rest. |
| `R7`, `L7` | 7-block long goal push with wings out. Used in eliminations. |
| `R4`, `L4` | 4-block variants of the long goal push. |
| `LRush9`, `RRush9` | 9-block rush that wins autonomous against a strong opponent. |
| `LQuals`, `RQuals` | Early qualification routines. |
| `Skills`, `Skills2`, `Skills21`, `Skills3` | Programming skills, in order of development. |
| `TestAuto` | Scratch routine used to tune the scoring sequence. |

### Skills autonomous

Skills went through several rewrites. We started with a simple route worth 76 points, then wrote a longer route with a maximum of 84 points that clears all four loaders, controls both long goals, and clears a park zone. It runs loader, long goal, cross the field, repeat. `Skills2` kept the same path but rewrote the timing for consistency.

## Building

1. Install the [PROS CLI](https://pros.cs.purdue.edu/v5/getting-started/index.html).
2. Create a new PROS project, then install EZ-Template 3.2.2:
   ```bash
   pros conduct fetch EZ-Template@3.2.2.zip
   pros conduct apply EZ-Template
   ```
3. Copy `src/`, the four headers in `include/`, and `project.pros` over the generated files.
4. Build and upload:
   ```bash
   pros make
   pros upload
   ```
